Design tokens

Every colour, size and duration in this bible is generated from docs/design/tokens.json. Run npm run design to regenerate the theme's SCSS custom properties, check contrast, and rebuild this document. Swatches show light and dark values.

Brand red rules

Brand red #EE0700 is kept exactly (header colour on the live site). Measured contrast: black on red is 4.67:1; white on red is 4.50:1, an AA pass by 0.0008 and not AAA for either. Because the white margin is that thin, anti-aliasing or any opacity can tip it under.

  • Default to black text (--color-on-brand) on red.
  • White on red only for large or bold text, never for small body text or thin icons.
  • Red text or links on light surfaces use --color-brand-text, a darker red. Plain #EE0700 on white is also only 4.50:1.
  • Never place red text on the red surface, or pale text on amber.

Type

Interim stack: Poppins then the system UI stack. The final font is decided later from Google fonts and default system fonts; whichever is chosen is self-hosted as a subset woff2 with font-display: swap. Base is 16px/24px; sizes are rem so user font settings and 400% zoom work.

3xl 2.25rem, page title

2xl 1.75rem, section heading

xl 1.375rem, card heading

lg 1.125rem, lede

base 1rem, body text on a 1.5 line height

sm 0.875rem, secondary and captions

xs 0.75rem, legal only; never for essential information

Theme config mapping

Core colours are exposed in config.json so the store admin can adjust them; node scripts/generate-design-tokens.mjs reports where config defaults differ from these tokens. Contrast is re-checked at build, so a bad admin choice must also be caught by the in-theme guard (to be specified in the implementation brief).

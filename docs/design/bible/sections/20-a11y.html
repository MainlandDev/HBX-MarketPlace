Accessibility playbook

Baseline WCAG 2.2 AA, with AAA adopted where it costs little (the contrast table marks AAA per pair). Accessibility is a build rule, not a review step: artistic intent is preserved by tuning tokens, not by relaxing the rule.

Structure

  • Landmarks: header, nav (each labelled), main, footer. Heading levels descend without skipping.
  • Links are links, actions are buttons. Whole-card links expose one name, not the image alt plus the title twice.
  • Page title and lang="en-AU" on every page.

Interaction

  • Focus is always visible: 3px ring using --color-focus, offset 2px, 3:1 against both themes (checked).
  • Focus is never hidden under sticky headers: sticky elements set scroll-padding-top and the page offsets anchors (WCAG 2.2 focus not obscured).
  • Target size at least 24x24 CSS px (AA); aim for 44px on touch controls. Buttons in this bible are 44px tall.
  • Everything works by keyboard; no keyboard traps; menus and dialogs return focus to their trigger.
  • No drag-only interaction (gallery swipe has buttons). No gesture timing.
  • Do not require re-entering information in the same checkout flow; show errors next to fields and in a summary.

Forms

  • Every control has a visible <label>; placeholders are never the label.
  • Required and format hints are text, linked with aria-describedby.
  • Errors: plain-language message, tied to the field, announced once via role="alert" or a live summary; colour is never the only cue.
  • autocomplete tokens on name, address, email, phone and card fields.

Colour, themes and motion

  • Light follows the design, dark follows prefers-color-scheme, and a toggle stores the visitor's choice. Without JS the page follows the OS.
  • Every token pair is contrast-checked in both themes at build time; AA failures fail the build.
  • prefers-reduced-motion: reduce sets motion tokens to 0ms; carousels do not autoplay, and any motion over 5 seconds has a pause control.
  • Information is never conveyed by colour alone (stock status, errors, selected variant use text or icons too).

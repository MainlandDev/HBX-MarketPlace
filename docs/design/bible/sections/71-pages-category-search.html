Page spec: Category and search

One listing layout for category, brand and search results. Filters and sorting are links and a GET form first; the island only makes them faster.

Header Breadcrumbs h1 Category name + result count Filters (aside, details groups) | Sort select Product grid: 2 columns mobile, 3 tablet, 4 desktop Pagination Category description (static text) Footer
Landmarksmain holds the results; filters in a labelled <aside> (or <form> with a heading); breadcrumbs and pagination are labelled <nav>s.
MobileFilters collapse into a <details> "Filter and sort" above the grid.
ComponentsBreadcrumbs, facet filters and sort, product card, pagination, buttons.
DataServer renders the first page of products and the facet list. The filter island sends one GraphQL request per filter change, deduped and cancellable; the URL always reflects the filters.
No JS"Apply filters" submits a GET to the same URL; every facet value and page is a real link.
StatesLoading (skeleton cards, aria-busy), empty (clear explanation and a "Clear filters" link), error (retry button, form submit still works).
A11yResult count in a polite live region after changes; focus stays on the changed control; no infinite scroll (pagination).
SearchSearch results page reuses the layout; "No results" offers spelling suggestions and category links.

Decoration filters (embroiderable, printable): second pass.

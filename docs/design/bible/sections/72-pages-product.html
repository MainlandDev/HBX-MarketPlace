Page spec: Product

The product page is where most of the interactive weight lives, and where the no-JS fallback matters most: a visitor can always choose options and add to cart with plain form controls.

Header, breadcrumbs Gallery (scroll-snap strip + thumbnails) h1 Product name, brand, price, stock Variant selector: colour swatches then sizes Quantity + Add to cart Delivery and returns notes Description / specs / size guide (details tabs) Reviews Related products Footer
LayoutMobile: single column, add to cart after options. Desktop: gallery left, buy box right, sticky only if it never obscures focused fields.
ComponentsBreadcrumbs, gallery, price and badges, variant selector, quantity and add to cart, FAQ-style details for specs, reviews, product cards.
DataServer renders product, options and initial variant data. The variant island receives the product id and storefront token from the template (existing colour-size.tsx pattern) and issues one batched availability query for all option combinations, shared with the gallery and price islands.
No JSNative radio inputs for every option; add to cart is a form POST; gallery is a stacked or scroll-snap list; specs are <details>.
StatesOut of stock, unavailable combination (explained in text), loading availability (selection still allowed), added to cart (live message), error.
A11yOne h1; fieldsets for option groups; swatch names are text; price change after selecting a variant is announced politely.
Structured dataProduct JSON-LD (name, image, offers, availability) and BreadcrumbList.

Decoration and branding step (logo placement, embroidery, print options) on the product page: second pass; this layout reserves the space between options and add to cart.

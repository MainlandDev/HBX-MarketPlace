Page spec: Cart and checkout entry

The cart is a plain server-rendered form. Checkout itself is the platform's hosted checkout and is out of scope for restyling here, but the handoff must be clear and accessible.

Header, breadcrumbs h1 Your cart (n items) Line items: image, name and options, price, quantity, remove Coupon / gift certificate (details) Shipping estimate (form) Summary: subtotal, savings (spend-and-save tiers), total Checkout button (primary) + continue shopping link Footer
ComponentsButtons, form controls, price, promo banner (tier progress as text, "Add $X more to save 15%"), mini cart (hidden on this page).
DataServer renders the cart. Quantity updates are form posts; with JS an island updates the line and summary with one request and replaces the region.
No JSQuantity input with an "Update" button; remove is a button in the line's form; coupon and shipping estimate are forms; the Checkout button is a link to the platform checkout.
StatesEmpty cart (message, link to categories), updating (aria-busy), item unavailable (explained), error with a retry that keeps what the visitor typed.
A11yLine items in a table or list with clear names for each button ("Remove Hi-vis polo, size M"); the total and tier progress are text; updates announced politely; no timeouts.
Checkout handoffThe button states that checkout opens the secure checkout; the page the platform serves is kept visually consistent where its settings allow (colours, logo).

Decoration details on cart line items (artwork preview, set-up fees): second pass.

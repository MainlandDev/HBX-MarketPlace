# Visual parity deviations

Where the theme intentionally differs from https://www.onlineworkwear.com.au/ (bible wins on structure, a11y, self-hosted assets, no-JS; live site wins on colours, spacing, layout, imagery). Plan: `docs/superpowers/plans/2026-11-26-visual-parity.md`.

Baseline (2026-11-26, before any parity change): `npm run design` passes (32 pairs AA), `npx vitest run scripts` 100/100.

| Section | Live behaviour | Ours | Bible rule |
| --- | --- | --- | --- |
| Fonts | Poppins from Google Fonts CDN | Poppins self-hosted and inlined as data URIs in `assets/scss/settings/global/_fonts.scss` (400/600/700, latin, OFL; sources in `assets/fonts`). All `$fontFamily-*` settings now point at Poppins and the Google Fonts link and the WebFont loader script (`theme-bundle.font.js`) are removed from `base.tsx`: zero Google font requests. The store still injects two `dns-prefetch preconnect` hints to Google because `config.json` `body-font` and `headings-font` stay `Google_*` (changing them risks store font-picker validation); they make no requests | No runtime CDN |
| Header: nav | Row 2 shows a Categories button (mega menu), SALE, SERVICES, CATALOGUES, HELP & SUPPORT, mail/phone icons, Facebook/Instagram icons | Categories is a `<details>` that opens without JS; the category list sits in a 260px panel and children keep the existing Foundation sub-menus. Links are the store's nav pages. Mail (hard-coded /contact-support/ path) and phone (`settings.phone_number`) icons added with English aria-labels. Facebook/Instagram icons not done: they need the `social_icon_placement_top` store setting | No-JS browse; real store content |
| Header: search | Pill input plus magnifier button, always visible | Same at 801px and up. Below that the existing quick-search toggle stays. The form now has `action` and `method="get"` with `name="search_query"` so it works without JS (it was input-only) | No-JS browse |
| Header: colours | White text on `#EE0700` | White only on bold uppercase links (bible allows white on brand only for large/bold text, 4.50:1). Cart pill and search button use new token `brandDark` `#B30000` (white 7.2:1). Edge dark mode darkens the Categories button and panel (live has no dark mode) | AA contrast; light/dark themes |
| Header: legacy CSS | Store CSS styles bare `details` and `summary` | Overridden with scoped utilities on the Categories toggle | Static-first |
| Footer | Grey newsletter band, three link columns, copyright left and payment icons right | Same layout. Categories limited to 7 and brands to 9 (live shows fewer, signed-out). Payment icons depend on merchant settings (`show_accept_*`) that are off in this build. "Powered by BigCommerce" still shows (`show_powered_by` setting) | Real store content |
| Home: store widgets | Hero, Popular Categories, Popular Brands and other widgets are store HTML styled by merchant CSS | The merchant CSS ("OWW CUSTOMISATION") is ported to `assets/scss/vendor/oww/_oww-custom.scss`, with its `:root` custom properties mapped to `--sv-*`. Store markup stays store-owned and is styled by class hook (user's call). Home height fell from about 48,000px to 4,500px | Static-first; markup not theme-owned |
| Home: demos | n/a | Counter and CounterStatic island demos removed from `home.tsx` (they printed stray text); files in `src/client` untouched | n/a |
| Home: promo strip and banner | Yellow sitewide promo strip and black "Spend & Save" banner render from customer-group regions | Fixed: the new theme had dropped the legacy `{{#or (if customer_group_id ...)}}` region blocks (`PUBLIC_header_bottom`, `UNREGISTERED_...` etc.); `src/server/regionParts.tsx` restores them and `home_below_section1-9` were added. Verified as a guest (`[::1]:5173`). The preview toggles (`*_preview_regions`) are not defined in `config.json`, so only the group-id match applies | Store content |
| Product card | White card, 10px radius, 0.8px `#ddd` border, soft shadow, 12px padding | Same, using fixed light tokens `ink`, `inkMuted`, `inkBorder` (card stays light in dark mode because legacy page text does not follow dark tokens) | Contrast kept AA |
| Config defaults | Store settings: primary red, page bg `#F2F2F2` | `config.json` `color-primary` `#EE0700` (was `#757575`) and `body-bg` `#F2F2F2` (was `#ffffff`). Dev server must restart to pick this up | Brand red exact |
| Header: not yet | "Sign in / Register" stacked beside a user icon; yellow promo strip with countdown (store banner region); page bg `#F2F2F2` | Text links "Account / Sign out"; promo strip arrives with the Home banner work; page bg is still white here | Open: Task 4b and a global bg pass |
| Facets | Accordions collapsed by default | Expanded or collapsed per the store faceted-search setting `start_collapsed` (store data, not theme code); the markup supports both | Store content |
| Listing controls | Product filter text box; "Products per page" select; pagination in the action bar | Products-per-page select (`limit`, a plain GET control) and a top paginator on category pages ported from the legacy `components/products/filter.html`. The selected value reads the `products_per_page` context value (shows 8 locally, live shows 20). The text filter box is store JS and is not ported | No-JS browse |
| Variant-selector check | n/a | `node scripts/check-variant-selector.mjs` fails on `class="form-option-active-copy" aria-hidden="true"`: `swatch.tsx` has carried Tailwind utilities in that class since the earlier Tailwind conversion, so the exact-attribute assertion is stale. Inputs are byte-identical to the base commit. Left unchanged (tests are not weakened without approval) | n/a |
| Form input border | 0.8px `#c7c7c7` | `#8A8A8A` (config `input-border-color`). `#c7c7c7` on white is 1.7:1, below the 3:1 WCAG 1.4.11 needs for control boundaries (review F7) | AA non-text contrast |
| Product custom fields | "Features" as pill badges, other fields not shown in the info list | Other fields are hidden in the info list only when the Custom Fields tab setting is on (they are listed there); with it off they show in the info list, so no data is lost (review F3) | No data loss |
| Product regions | Store widgets below rating and price (e.g. "Super Saver") | Customer-group and plain regions `product_below_rating(--global)` and `product_below_price(--global)` restored. Decoration regions (`*_product_above/below_options--global`, `product_below_add-to-cart--global`, `product_below_product-details--global`) stay out of scope (decoration brief) | Store content |
| Product brand label | 16px bold uppercase `#9C9C9C` | 16px bold uppercase `ink-muted` (`#454545`): `#9C9C9C` is 2.7:1 on white, below AA | AA contrast |

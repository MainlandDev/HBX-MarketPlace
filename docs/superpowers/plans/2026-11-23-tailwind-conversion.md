# Tailwind Conversion Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build the SCSS-to-CSS-variable bridge, a Tailwind theme layer on top of it, a computed-style verification toolchain and a playbook, then prove the loop by converting the variant selector.

**Architecture:** A Node generator scans `assets/scss/settings/**` for top-level `$variables` and writes a committed `_css-vars.scss` that emits each as `--sv-*` on `:root` through a guard mixin. `_tailwind.scss` gains an `@theme inline` block mapping readable names to those vars (and to the design-token vars). A Chrome-run snapshot expression plus a diff script verify that converting markup to utilities does not change computed styles.

**Tech Stack:** Node ESM `.mjs` scripts, Vitest (`scripts/**/*.test.mjs`, already in `vitest.config.ts`), Tailwind v4 via `@tailwindcss/postcss`, libsass via `node-sass` (BigCommerce's compiler), claude-in-chrome tools for capture.

**Spec:** `docs/superpowers/specs/2026-11-23-tailwind-conversion-design.md`

## Global Constraints

- Bridge prefix is `--sv-`; the name is the SCSS variable name without `$`, case preserved (`$color-primaryDark` -> `--sv-color-primaryDark`).
- Generated files carry a `// GENERATED by ... Do not edit.` header and are committed; a `--check` mode fails when stale (same pattern as `scripts/generate-design-tokens.mjs`).
- Only `_tailwind.scss` is processed by Tailwind. No `@apply` classes. No new npm packages.
- Tailwind input may not contain `$vars`; it may contain `var(--x)`.
- About 10 utilities per element; beyond that, or for repeated structures, extract a TSX component.
- libsass compatibility: no `@use`, no `math.div`; use `type-of`, `length`, `#{}`.
- Tests are `scripts/tailwind/*.test.mjs`, colocated with their module. Match the existing style in `scripts/design-tokens/`.
- Commits: Conventional Commits, subject at most 50 chars, one per task, never touching unrelated partials. `CHANGELOG.md` uses CRLF: edit with `\r\n`-aware replacement and confirm with `git diff`.
- Rulings recorded here: (1) scan scope is `assets/scss/settings/**` only, not component partials, because the bridge is imported after settings and component-local variables do not exist yet at that point (spec said "theme-owned"; this narrows it). (2) Drift reconciliation between `config.json` and `tokens.json` is NOT in this plan: each of the 6 keys needs the user's choice.

## Review Focus

1. A comma list value (`$font-family-sans: Arial, sans-serif`) must be emitted, not skipped as a "list"; only maps, `null`, booleans and empty lists are skipped.
2. A multi-line declaration (value spans lines, e.g. a parenthesised list) is scanned as one variable; indented declarations inside `@if` or mixins are not top-level and are ignored.
3. A variable declared twice appears once in the output and is reported as a duplicate (Sass uses the later value, and so does the bridge since it reads the variable at import time).
4. The theme layer must not create a self-reference: `--color-brand: var(--color-brand)` must not appear in the Tailwind output (`@theme inline` does not emit theme vars).
5. A converted element must render identically with JS off (`html.no-js`), not only with JS on.

### Task 1: Bridge generator

**Files:**
- Create: `scripts/tailwind/bridge.mjs`, `scripts/tailwind/bridge.test.mjs`, `scripts/generate-bridge.mjs`
- Create (generated): `assets/scss/settings/global/_css-vars.scss`
- Modify: `assets/scss/theme.scss` (add one import), `package.json` (two scripts)

**Interfaces:**
- Produces: `scanVariables(files: {path: string; text: string}[]): {names: string[]; duplicates: string[]}` and `renderBridge(names: string[]): string`.
- Consumes: nothing from earlier tasks.

- [ ] **Step 1: Write failing tests in `scripts/tailwind/bridge.test.mjs`.** Cases, each asserting exact output:
  - `scanVariables` finds `$color-primary: stencilColor("color-primary");` and `$gap: 1rem !default;` as names `color-primary`, `gap`.
  - Ignores a `$x: 1;` that is indented (inside `@if`), inside `/* */` and inside `//` comments.
  - A multi-line value (`$list: (\n  a,\n  b\n);`) yields one name `list`.
  - Names are unique, in first-seen order across files; a name declared twice is returned once in `names` and once in `duplicates`.
  - `renderBridge(["a","b"])` contains the header `// GENERATED by scripts/generate-bridge.mjs`, a `@mixin sv($name, $value)` whose guard excludes `null`, booleans, `map` and empty lists, then `:root {` with `@include sv("a", $a);` and `@include sv("b", $b);`.
  - Output for the same input is byte-identical on a second call.

- [ ] **Step 2: Run to verify failure.** Run: `npx vitest run scripts/tailwind/bridge.test.mjs`. Expected: FAIL, module not found.

- [ ] **Step 3: Implement `scripts/tailwind/bridge.mjs`.** Strip block and line comments first (as `plainCss` does in `bible.mjs`), then match column-0 declarations with a multiline regex (`/^\$([\w-]+)\s*:\s*[^;]+;/gm`). The mixin body: `@if $value != null and type-of($value) != "bool" and type-of($value) != "map" and not (type-of($value) == "list" and length($value) == 0) { --sv-#{$name}: #{$value}; }`.

- [ ] **Step 4: Run to verify pass.** Run: `npx vitest run scripts/tailwind/bridge.test.mjs`. Expected: PASS.

- [ ] **Step 5: Implement the CLI `scripts/generate-bridge.mjs`** (`--write` / `--check`, modelled on `generate-design-tokens.mjs`). It reads every `.scss` under `assets/scss/settings/` except `_css-vars.scss`, prints `declared N, duplicates M (names)`, writes or checks `assets/scss/settings/global/_css-vars.scss`. Add `package.json` scripts `generate-bridge` (`--write`) and `check-bridge` (`--check`). Run `npm run generate-bridge`.

- [ ] **Step 6: Wire the import.** In `theme.scss`, add `@import "settings/global/css-vars"; // generated: SCSS variables as --sv-* custom properties` directly after the `design-tokens` import line.

- [ ] **Step 7: Compile check with libsass.** In the session scratchpad write a harness `.scss` that defines stub functions `stencilColor`, `stencilNumber`, `stencilString`, `stencilBoolean` (returning a fixed colour, `1`, `"x"`, `false`), then mirrors the imports of `theme.scss` lines up to and including the new `css-vars` import (skip `@import "./tailwind"`). Run `npx node-sass --include-path assets/scss <harness> > <out.css>`. Expected: exit 0; `out.css` contains `--sv-color-primary:` and contains no `--sv-` line with an empty value and no `map-get` text. If a settings file needs a mixin or function defined later, fix the generator's scope or import order and record a `Ruling:`.

- [ ] **Step 8: Run `npm run check-bridge` (expect "up to date") and `npx vitest run` (full suite green), then commit.**

### Task 3: Computed-style snapshot and diff

**Files:**
- Create: `scripts/tailwind/snapshot.mjs`, `scripts/tailwind/snapshot.test.mjs`, `scripts/tailwind-diff.mjs`
- Modify: `package.json` (script `tw-diff`)

**Interfaces:**
- Produces:
  - `DEFAULT_PROPS: string[]` (about 40 layout and paint properties: display, position, box model, flex/grid, typography, colours, border, radius, shadow, opacity, overflow, z-index, gap, transform).
  - `buildCaptureExpression({root: string, props?: string[]}): string`: JavaScript source that, run in a page, returns `Record<string, Record<string, string>>` keyed by structural path (`div:nth-child(2)>a:nth-child(1)`, relative to the root element, root itself keyed `"."`), value = computed style per property.
  - `diffSnapshots(before, after): {path: string; property: string; before: string; after: string}[]`; a path present on one side only yields `property: "(element)"` with `"present"`/`"missing"`.
- Consumes: nothing.

- [ ] **Step 1: Write failing tests in `snapshot.test.mjs`.**
  - `diffSnapshots` returns `[]` for equal snapshots, one entry for one changed property, `(element)` entries for added and removed paths.
  - `buildCaptureExpression({root: ".x", props: ["color"]})` evaluated with `node:vm` against a stub (`document.querySelector` returning a root with `children`, `parentElement`, `tagName`, `querySelectorAll("*")`; `getComputedStyle(el).getPropertyValue(p)`) returns exactly the expected keys and values, independent of class names.

- [ ] **Step 2: Run to verify failure.** Run: `npx vitest run scripts/tailwind/snapshot.test.mjs`. Expected: FAIL, module not found.

- [ ] **Step 3: Implement `snapshot.mjs`** (path computed by walking `parentElement` and counting position among `parent.children`, tag lower-cased). **Step 4:** run the tests. Expected: PASS.

- [ ] **Step 5: Implement `scripts/tailwind-diff.mjs <before.json> <after.json>`:** prints one line per difference, `N differences` or `identical`, exit 1 when any. Script `tw-diff`: `node scripts/tailwind-diff.mjs`.

- [ ] **Step 6: Run `npx vitest run` (green) and commit.**
